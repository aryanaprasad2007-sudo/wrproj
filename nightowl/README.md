# NightOwl

A desk setup for someone who sleeps at 01:30, wakes at 07:30, works at the
computer all day, watches a lot of anime, games in the evening, and answers to
nobody about how they spend the hours in between.

It does these things:

1. **Moves the screen through the day** — 6500K while you work, rolling down to
   2500K past bedtime, in software, on a curve. Keyboard and mouse RGB follow
   the same curve if the Chroma daemon is running.
2. **Switches the whole machine between modes** — one keystroke changes power
   plan, notifications, Game Mode, display sleep and the live wallpaper together.
3. **Interrupts you on purpose, and only when it should** — eye and posture
   breaks that skip themselves if you're gaming, idle, fullscreen, or in a
   calendar block you already built your own breaks into (Deep Work, Homework).
   Prayer Closet blocks get notifications auto-muted, no mode switch needed.
4. **Tracks the anime season** — what airs tonight, what you're behind on, with
   direct links to search for it, and a weekly digest command for Notion.
5. **Surfaces what actually matters today** — your real Google Calendar, the
   Notion Command Center's open tasks, The Docket's Top 5/slips/cross-checks,
   and the iAPE desk's regime/signals, all on one page instead of five.
6. **Turns real focus into real EXP** — a completed focus-timer block, or a
   wind-down that holds for 3+ hours without you overriding back to work/game,
   credits your Solo Leveling System dashboard - additively on top of whatever
   the webcam Productivity Coach already tracks, never double-counted.

Everything is HKCU-scoped and reversible. `uninstall.ps1` puts it all back.

## The dashboard

`no hub`, or `Ctrl+Alt+H`, or the desktop shortcut.

**These now open PSYCHOWL** (`http://127.0.0.1:8787/`, served by
`wrproj/src/dashboard.py`), not the static page in `hub/`. `no hub` pings
`/api/psychowl` first and starts that server headless if it's down. NightOwl
appears there as a *rhythm* card - mode, wake, bedtime, focus banked, and
tonight's wind-down walkthrough one step at a time once it's actually running.

That last part is served from `config.json`'s `nightRoutine` via
`psychowl_data.nightowl()`. Before 2026-08-17 it wasn't: the routine rendered
only on `hub/index.html`, which nothing had opened since `no hub` was
repointed - so the gentlest content in the system was reaching nobody. If you
edit the routine copy, that is the path it travels.

### hub/index.html is legacy

Still generated by `no sync` and by `NightOwl_AnimeSync` at 09:00, still
correct, and still openable directly as a `file://` page - but nothing routes
to it any more. It carries the circadian ribbon (Awake / To Bed / To Wind-down
ticking to the second), the **Today** agenda, the **Command Center** card, an
**iAPE desk** tile, mode buttons, a focus timer, this season's anime with watch
links, and app/Steam launchers. Keep it or retire it; just don't assume a copy
change there reaches the screen.

The buttons work through a `nightowl://` URL protocol registered under your user
account — clicking "Game mode" in the browser genuinely flips the power plan.

The page switches to a warm plum theme by itself at wind-down. It is not a black
void; it stays readable.

## Claude Code

- `/nightowl` — pulls today's remaining Google Calendar events and open Notion
  Command Center tasks live, rebuilds the Hub, and reads the state back: where
  the day stands, what's next, one thing worth doing, anything overdue worth naming.
- `/nightowl <topic>` — a different mode entirely. Instead of a status read, it
  spins up a new Notion page for whatever you typed, under 🌸 main notion page
  (same spot every standalone `<Topic> Plan` page already lives), with a short
  framing and a generated **Next steps** list. That list is illustrative
  scaffolding for you to edit, not verified fact — this is a capture tool, not
  a research tool.
- `/winddown` — flips the machine into wind-down, then helps you close the loop
  that would otherwise keep you up until 3.
- `/anime` — what's airing in the next 24 hours, what you're behind on.
- `/anime digest` — posts a Notion page with episodes watched since the last
  digest (an exact count it tracks itself, not an estimate) and current backlog.

The status line shows phase, hours awake, time to bed, and current mode.

**On the calendar sync:** the Hub's Today card is a snapshot, refreshed only
when `/nightowl` actually runs. The `NightOwl_*` Windows scheduled tasks run
unattended and have no Google credentials of their own, so they can't pull it
automatically — only an interactive Claude Code turn can, via the connected
Calendar MCP tool. `python/calendar_cache.py` does the normalizing/deduping/
sorting once Claude hands it the raw events.

## What runs on its own

| Task | When | Notes |
|---|---|---|
| `NightOwl_Screen` | every 15 min | re-applies the colour curve (skips in anime mode) |
| `NightOwl_EyeBreak` | every 25 min | skips if idle >3 min, gaming, fullscreen, or a protected calendar block |
| `NightOwl_CalendarCheck` | every 10 min | mutes/restores notifications around Prayer Closet blocks |
| `NightOwl_Posture` | hourly | same skip rules as the eye break |
| `NightOwl_GameCheck` | every 15 min | one nudge when a session passes 2h |
| `NightOwl_WindDown` | 00:30 | warms and dims, notifications back on |
| `NightOwl_Bedtime` | 01:30 | gentle late card, deep dim, power saver |
| `NightOwl_AnimeSync` | 09:00 | refreshes the season, rebuilds the Hub |
| `NightOwl_ExpSync` | 07:50 | regenerates the Solo Leveling dashboard - picks up last night's clean-wind-down bonus |
| `NightOwl_ChromaStart` | at logon | starts the ambient RGB daemon |
| `NightOwl_Logon` | at logon | picks the right mode for the time of day |

The break tasks are deliberately hard to annoy you with. If you're away from the
desk, mid-game, watching something fullscreen, or in a block you already
designed your own breaks into (Deep Work, Homework both say "protected block,
do not move" in their own descriptions), they say nothing.

**Missed runs are dropped, not replayed.** Every task that speaks to you or
changes the machine's mode is registered *without* `StartWhenAvailable`. With
it on, a PC that was off overnight boots and Task Scheduler fires the whole
missed night at once - which on 2026-08-17 meant WindDown and Bedtime both
running at 10:59 AM, a "past bedtime" card in the late morning, and the mode
stuck at `sleep` all day. It also silently doubled every repeating task,
because the replayed instance carries its own copy of the repetition block and
runs alongside the real schedule. A missed break is just a break that no longer
applies; skipping it is correct. `NightOwl_AnimeSync` and `NightOwl_ExpSync`
keep catch-up, since they say nothing and only refresh data.

Belt and braces: `WindDown` and `Bedtime` also pass `-Scheduled`, and
`Invoke-NOMode` refuses a scheduled time-of-day mode the clock no longer agrees
with. Manual calls are never blocked - ask for wind-down at noon and you get it.

**Protected blocks and quiet hours read `data/calendar.json`**, same freshness
caveat as the Today card below - only as current as the last `/nightowl` run.
**If that file is more than 24h old the engine now says so in the log** and
treats it as unknown. It always treated stale data as "no event known", which
is the right call, but that is indistinguishable from "nothing is on right now"
- so from 2026-08-04 to 2026-08-17 protected blocks and quiet hours were both
effectively off and nothing reported it. `protectedBlockKeywords` has the same
failure mode: it is matched against real event titles, so when the shape of the
week changes the list quietly stops matching anything. Re-read it whenever the
calendar changes; it was last checked against live events on 2026-08-17.

## Config

Everything lives in `config.json`. The interesting knobs:

```jsonc
"wake": "07:30",              // anchors the whole day model
"bedtime": "01:30",           // after midnight is handled correctly
"windDownMinutes": 60,        // how long before bed things start warming
"eyeBreakMinutes": 25,
"gameBudgetMinutes": 120,     // one nudge, not a lock
"warmth": {
  "dayKelvin":   6500,        // neutral
  "nightKelvin": 3300,        // wind-down
  "lateKelvin":  2500,        // past bedtime
  "animeKelvin": 4800         // slightly warm, still true-ish colour
},
"calendarAwareness": {
  "protectedBlockKeywords": ["Deep Work", "Homework", "Protected", "Study"],
  "quietBlockKeywords": ["Prayer Closet", "Prayer"]
}
```

Change bedtime and re-run `install.ps1` to move the scheduled tasks with it.

`gameProcesses` is the list that suppresses break nudges — add anything that
isn't already there.

## How the screen control works

Windows Night Light is on/off with a slider and no schedule you can script. This
uses `SetDeviceGammaRamp` instead — the same mechanism f.lux uses — which gives
per-channel control of the display's output curve.

A colour temperature in Kelvin is converted to RGB multipliers using the Tanner
Helland blackbody approximation, then written as a 256-entry ramp per channel.
Brightness is folded into the same ramp, so it dims below the monitor's own
minimum without touching the backlight.

It needed no elevation on this machine and the full range was available — a
3400K request landed exactly on target, not clamped.

Trade-off: gamma ramps don't apply inside exclusive-fullscreen games, and they
don't show up in screenshots. That's the mechanism, not a bug.

## Connections to your other projects

NightOwl links to three sibling projects under `wrproj/` without duplicating
what they already do well:

- **Solo Leveling System** — finishing a NightOwl focus-timer block fires
  `nightowl://focus/complete/<min>`, which appends to
  `nightowl/data/focus_sessions.json` and immediately regenerates
  `Solo-Leveling-System/solo_leveling_live.html` via its own `system_bridge.py`.
  That script also scans `nightowl.log`'s `MODE -> sleep`/`work`/`game`
  transitions for **clean wind-down nights** - a flat +20 EXP bonus, once per
  night, if sleep mode held for 3+ hours before the next override. Both
  sources use their own idempotent per-day ledger (`nightOwlFocusLog`,
  `nightsLog` in the app's `slSystem_v1` localStorage), fully separate from the
  webcam Productivity Coach's existing `focusLog` ledger, so nothing can
  double-credit and the two streams can never fight over the same day's
  numbers. **Caveat, stated plainly:** if the coach and a NightOwl focus block
  ever run at the same real-world time, both streams still pay out - this is a
  gamification layer, not an audit system, and no attempt is made to
  deduplicate overlapping minutes across the two sources.
- **The Docket** — the Hub reads `Daily-Docket/docket_data.json` and
  `slips.json` (both written once daily by the existing `daily-docket`
  scheduled task) and surfaces Top 5, items slipping 2×+, and non-info
  cross-check flags as a read-only card, with a link straight to the live
  artifact. NightOwl's own Command Center card keeps pulling Notion live and
  independently - the two aren't reconciled, since the Docket's slip-tracking
  and anti-rot logic is already mature and NightOwl has no reason to
  re-implement it.
- **Solo Leveling / Docket / Docket PWA** all get a direct launch link on the
  Hub too (`links` in the Hub payload) - plain file:// / https:// anchors, no
  `nightowl://` indirection needed since they're not registered executables.

## Why the protocol handler is a compiled .exe

`bin/nourl.exe` (built from `bin/nourl_launcher.cs` by `install.ps1`, via the
.NET Framework's `csc.exe` — no project file needed) is what `nightowl://`
actually launches. It didn't start out that way; a `.vbs` entry point kept
failing silently for one specific launch path.

Chromium's external-protocol handling resolves `shell\open\command` through
Windows' association API (`Shell.Application` COM automation, not a plain
`ShellExecute` call) — and on this machine that resolver silently **drops
every argument** once the command has more than two tokens: an explicit
interpreter (`wscript.exe`) plus a separate quoted script path plus `%1` came
back as just `wscript.exe`, arguments gone. Dropping the explicit interpreter
and pointing straight at a quoted `.vbs` path didn't fix it either — resolving
a `.vbs` needs a second hop (`.vbs → wscript.exe`) that reproduces the exact
same corruption. A compiled `.exe` as the sole quoted target is the one shape
that survives, because there's no second hop to get wrong: exactly two tokens,
`"nourl.exe" "%1"`, one association lookup.

If you ever need to touch this, keep it to that shape. Verify with
`AssocQueryString(ASSOCSTR_COMMAND, ...)` from `shlwapi.dll` (returns the same
truncated-or-not result the browser sees) rather than testing through `explorer.exe
<url>` on the command line — that path goes through a different, older resolver
with its own unrelated quirks and isn't representative of what a browser does.

## `$Args` is a reserved name — never use it as a parameter

`install.ps1` builds every task and shortcut command line from one string:
`"<nohidden.vbs>" $LaunchArgs`. That second variable used to be called `$Args`,
which is PowerShell's **automatic** variable (the unbound-argument array).
Declaring `param($Name, $Args, $Trigger, $Desc)` raises no error and no warning
— the automatic version simply wins, so `$Args` reads back as empty and every
verb was stripped on its way into the registered command.

The failure was invisible in both directions:

- **Tasks** got `nohidden.vbs` with no verb, so `no.ps1` fell through to its
  `[ValidateSet]` default of `status` — a read-only print. Eleven tasks ran on
  schedule for a week, every one reporting `LastTaskResult = 0`, while no eye
  break, posture nudge, screen curve, wind-down or chroma pass ever fired. The
  only trace was `logs/nightowl.log` going quiet.
- **Shortcuts** were written by an older revision that had *also* lost `$Bin`,
  producing `wscript.exe "\nohidden.vbs"` — no directory at all. `wscript`
  resolves a leading `\` against the current drive root, so every Start Menu
  and desktop click raised *Can not find script file `C:\nohidden.vbs`*. The
  same shape with the pre-`.exe` protocol handler is where `C:\nourl.vbs` came
  from.

Guards now in place: `install.ps1` throws if `$PSScriptRoot` or the launcher
path is empty rather than baking a relative path into the registry, and
`bin/nohidden.vbs` logs a `launcher WARN` when it is invoked with no action.
After changing anything in the install script, re-run it and confirm the verbs
actually survived:

```powershell
Get-ScheduledTask -TaskName "NightOwl_*" | ForEach-Object { "{0,-24} {1}" -f $_.TaskName, $_.Actions[0].Arguments }
```

## Things worth knowing

- **FancyZones layouts** — "NightOwl Desk" (4 zones: reference / main / two
  stacked right) and "NightOwl Focus" (3 zones) are installed. PowerToys owns
  which layout is *applied* and rewrites that file on exit, so pick one once in
  the FancyZones editor (`Win+Shift+\``). The layouts are already in the list.
- **Anime mode disables display sleep.** If you fall asleep watching, the 01:30
  bedtime task drops it back to a 5-minute timeout, so the screen won't burn all
  night.
- **The wind-down nudge is the only opinionated thing here.** It appears once at
  00:30 and once at 01:30 and then leaves you alone. Sleeping ~6 hours is your
  call; the setup just makes sure the choice is deliberate rather than accidental.
- **First `nightowl://` click** will make Brave ask whether to open NightOwl.
  Tick "always allow" and it won't ask again.

## Removing it

```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1
```

Removes the tasks, the protocol, the shortcuts, the profile block and the hotkey
autostart, and restores gamma, notifications, power plan and Game Mode. The
folder stays; delete it by hand. PowerToys and AutoHotkey were installed
separately — remove them from Settings → Apps if you want them gone.
